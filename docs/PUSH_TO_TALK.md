# Push-to-talk

Open **All settings → PC control → Push-to-talk**. The switch enables or disables your saved shortcut directly. Click the shortcut button to change it; if no valid key is saved, enabling also opens this picker. Press a key or chord, then choose **Save & enable**. Cancel keeps the previous setting. The microphone is paused while this dialog is open and resumes when it closes, is removed, or its settings view is replaced. Enable the microphone in AI & voice before using the shortcut.

Windows supports letters, F1–F12, Space, Insert, Pause and Caps Lock, with optional Ctrl, Alt and Shift. The shortcut remains active while another application has focus, and also reaches that application; choose one that does not conflict with its controls. Windows-key combinations and Alt+F4 are not accepted.

Hold the chosen key to talk and release it to send. Groq records a maximum of 30 seconds per hold, ignores silence and accidental taps, and sends no unheld audio. Its continuous speech detection remains available with push-to-talk disabled. Gemini keeps its server voice detection and receives an end-of-audio marker on release, following the [Gemini Live API guidance](https://ai.google.dev/gemini-api/docs/live-api/capabilities). Microphone mute, screen lock, sleep and key-picker suspension close the gate. A shortcut helper failure displays a reconnecting message and retries automatically. Release the shortcut before a new press after recovery.

The Windows helper polls only the chosen chord and modifier state, reports transitions plus a one-second heartbeat, and does not record typed text. Startup permits up to 60 seconds for PowerShell compilation; heartbeat loss must last 20 seconds before recovery starts. Retries back off from one to 30 seconds. Electron owns this helper for both providers; Gemini's separate fixed Ctrl+Space listener is disabled in the desktop application. The optional standalone Qt HUD reads the saved chord instead.

Changing the shortcut or toggling push-to-talk sends live configuration to Gemini without restarting Python. Settings are applied before the voice coordinator synchronizes provider/microphone state. Switching providers cancels old local speech and ignores stale transcription results. Engine replacement waits for the old Windows process tree to terminate, ignores callbacks from retired processes, and cancels automatic retries on intentional stop or application exit.

Validation covers shortcut parsing, press/release transitions, slow startup, heartbeat recovery, buffer isolation, release submission, cancellation, late microphone permissions, live Gemini configuration and PCM/end-marker ordering, stale engine callbacks, and the actual settings picker. Renderer tests exercise both push-to-talk ON and continuous listening with it OFF, plus provider switches and picker cleanup. Native tests start the real Windows helper and simulate its crash, and terminate an owned parent/child process tree without injecting keyboard input. Live speech recognition and speaker/microphone hardware still need a test with the user's API key and devices.
