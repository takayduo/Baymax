# Quiet by default and click-to-stop

Under Settings → PC control, **Random / Proactive AI Talking (Time check-ins, sleep reminders & news)** is OFF by default. It controls spontaneous startup briefings, time/wellbeing check-ins, background news/system alerts and spoken focus warnings. Turning it off updates the live engine, cancels these tasks and stops any pending background speech. Gemini's separate Proactive Audio setting still controls whether it responds to background conversations; it does not enable unsolicited check-ins.

**My Interests & News Topics** saves up to 2,000 characters on this user's PC. Commas, semicolons or newlines separate topics. Blank interests disable unsolicited news searches. Settings sync to the engine's `api_keys.json`, prompt context and existing `memory/long_term.json` store (this app does not use a separate `memory.json`). Other memories are preserved. News queries and returned headlines must match saved interest words; unrelated old monitors are skipped. The prompt restricts suggestions to these preferences and forbids invented current headlines. This conservative matching may omit relevant articles; it is not a semantic classifier.

Clicking the companion sends a stop even if the renderer has stale voice status. It immediately closes the mouth, clears visemes/audio levels, aborts the speaker stream and invalidates queued audio batches. The startup briefing's second phase and background injections are cancelled. Trailing server turn completions, tool results and delayed renderer replies cannot release the stop. The latch survives live-engine replacement within the running app. A new typed prompt or two voiced microphone blocks after the mute/PTT/echo gates allow responses again. Closing and reopening the app begins a new session.

Regression tests exercise real production receive/playback methods with fake audio devices, renderer capture with a simulated microphone, and Electron event/process ownership. Live Gemini/Groq account calls and physical microphone/speaker behavior still require a real-device acceptance check.
