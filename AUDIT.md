**App discovery, monitoring, Overview and Insights**

1. **High — “Scan All Apps” is only a partial Start Menu shortcut scan.** [tracker.js:623](G:/baymax/electron/productivity/tracker.js:623) reads only `.lnk` files in two Start Menu folders. It requires an existing `.exe` target and rejects Windows-directory targets. Packaged/Store app identities, shortcuts through wrappers, and portable apps without Start Menu entries can be missed. The broad exclusion expression at line 630 also matches useful names containing `git`, `update`, `terminal`, or `console`; an `Update.exe --processStart ...` shortcut loses both the underlying app and its arguments. **Fix:** merge app registrations and AppIDs, resolved shortcut target/arguments, and observed foreground applications. Treat utility filtering as display policy and keep manual inclusion available. Microsoft's [Get-StartApps documentation](https://learn.microsoft.com/en-us/powershell/module/startlayout/get-startapps?view=windowsserver2025-ps) describes names and AppIDs for the current user's Start apps; use it as one source, not a claim of complete coverage.

2. **High — Junk remains in the persistent library after scanner fixes.** [tracker.js:191](G:/baymax/electron/productivity/tracker.js:191) cleans a different, much smaller list than the scanner filters. [tracker.js:677](G:/baymax/electron/productivity/tracker.js:677) merges into existing `knownApps` without reconciling obsolete entries. A zero-result scan returned all four seeded entries (`msiexec`, `wmplayer`, `scale`, `scalehost`) in the probe. The actual saved data contains the uninstall entry the user reported. **Fix:** add a versioned catalog migration and provenance (`shortcut`, `packaged`, `observed`, `manual`), remove stale installer/helper records from the visible catalog, and preserve real usage history and manual selections. Add Hide/Remove controls. Windows Terminal and Windows Media Player are real apps; whether they appear by default is a preference, unlike an uninstall command.

3. **High — Real apps are explicitly prevented from being monitored.** [tracker.js:12](G:/baymax/electron/productivity/tracker.js:12) ignores `antigravity`, `powershell`, `pwsh`, `cmd`, `explorer`, `applicationframehost`, and every process named `electron`. The same policy also deletes some existing records. Five ignored sample processes produced no usage in the probe. **Fix:** identify Baymax itself by PID/path, distinguish host processes from the applications they host, and keep “do not terminate” protection separate from “do not track.” Let the user decide whether terminal/file-manager activity counts.

4. **High — App identity is an executable basename, not a durable application identity.** The scanner deduplicates by basename at [tracker.js:642](G:/baymax/electron/productivity/tracker.js:642), drops the executable path from saved catalog entries, and the tracker keys usage by `processName.toLowerCase()` at line 379. Different installations can collapse together; wrappers and app names may not match running processes. The actual library contains `whatsapp.root`, while the default category is keyed as `whatsapp`. Custom-app entry can invent an identifier from the display name ([Classification.tsx:288](G:/baymax/productivity/src/pages/Classification.tsx:288)). **Fix:** use a canonical ID based on normalized executable identity or packaged AppID; retain launch arguments and aliases; select actual apps/processes when adding manually.

5. **High — Time accounting overcounts and assigns intervals to the newly observed app.** [tracker.js:374](G:/baymax/electron/productivity/tracker.js:374) rounds every elapsed sample to seconds, while the PowerShell loop samples every 1,500 ms. Forty simulated samples representing 60 seconds produced 80 recorded seconds. The elapsed interval is then credited to the newly sampled app, so an app switch can attribute the preceding time to the wrong application. **Fix:** accumulate milliseconds with a monotonic clock, close the preceding foreground interval on a switch, and round only when rendering. Define a maximum sampling gap and split intervals at local midnight.

6. **High — Valid tracking events can be lost at arbitrary stdout chunk boundaries.** [tracker.js:252](G:/baymax/electron/productivity/tracker.js:252) splits each received chunk and parses its pieces separately; an incomplete JSON line is silently discarded. The probe delivered one valid sample in two chunks and it disappeared. **Fix:** use a UTF-8 decoder and persistent newline buffer; serialize activity updates; expose parser failures and last-successful-sample time. The PowerShell helper also constructs JSON manually ([foreground_tracker.ps1:54](G:/baymax/electron/productivity/foreground_tracker.ps1:54)); use a proper serializer for control characters in window titles.

7. **High — Idle, screen lock and suspend are not modeled.** The tracker counts an unchanged foreground window while the user is away. Its fallback can select a visible desktop window when no trustworthy foreground window is available; long gaps are arbitrarily capped at 30 seconds. **Fix:** explicitly pause/count idle according to the product's chosen definition, stop accrual while locked/suspended, and reset timing on resume. Electron provides [idle time and lock/suspend events](https://www.electronjs.org/docs/latest/api/power-monitor). A foreground app with no recent user input should not automatically mean active work.

8. **Medium — The current-app state and tracker health can stay stale.** [tracker.js:381](G:/baymax/electron/productivity/tracker.js:381) returns for ignored processes before clearing `currentForeground`: Chrome remained the reported foreground after the simulated switch to Antigravity. The heartbeat at line 231 only restarts a missing/killed process, so a live but silent PowerShell child can stall indefinitely. **Fix:** clear or mark untracked/unknown foreground on every sample; expire it after a short freshness window; restart a silent child using a bounded backoff and show tracking health in the UI.

9. **High — Weekly data is overwritten by daily events.** [productivity.ts:38](G:/baymax/src/views/productivity.ts:38) always requests daily stats, and forwards live daily tracking messages. [AppContext.tsx:319](G:/baymax/productivity/src/context/AppContext.tsx:319) accepts those messages without checking the selected timeframe. The separate IPC listener/poller respects weekly mode, creating alternating daily and weekly results. **Fix:** have one data subscription/query owner; put the period in the response; discard responses for a different period or request revision.

10. **Medium — Insights and Focus Score discard short sessions.** [Insights.tsx:15](G:/baymax/productivity/src/pages/Insights.tsx:15) rounds each app's seconds to minutes before adding them, while Overview sums seconds first. Three apps used for 20 seconds each produce one minute in Overview and zero in Insights. [logic.ts:3](G:/baymax/productivity/src/utils/logic.ts:3) similarly computes score from individually rounded minutes. **Fix:** use the same seconds-based aggregation for every screen and format short usage as seconds or `<1m`.

11. **Medium — Empty/new-day data does not clear old UI values.** The poller and timeframe effect only accept non-empty arrays ([AppContext.tsx:387](G:/baymax/productivity/src/context/AppContext.tsx:387), line 416). `getKnownApps()` updates today's entries but does not reset entries absent today ([tracker.js:532](G:/baymax/electron/productivity/tracker.js:532)); the probe showed an empty today view with ten minutes still attached to a catalog app. “Clear Data” leaves `knownApps` usage values behind. **Fix:** separate static catalog metadata from usage, derive usage for the selected date on every read, and accept an empty result as authoritative.

12. **Medium — Date ranges and displayed app limits are inconsistent.** [tracker.js:490](G:/baymax/electron/productivity/tracker.js:490) uses a rolling seven days, but `getDailyTotals()` uses the current Monday–Sunday week. [Dashboard.tsx:45](G:/baymax/productivity/src/pages/Dashboard.tsx:45) highlights today using UTC while backend dates are local; in India this can highlight the prior day before 05:30. Overview displays only four top apps, Insights three productive and three distracting apps; neutral apps do not appear in those highlights. These limits are not proof of missing tracking. **Fix:** define one period/timezone contract and provide a complete usage list with an explicit Top Apps label.

**Focus mode and AI behavior**

13. **High — The backend does not end a focus session at its deadline.** [blocker.js:55](G:/baymax/electron/productivity/blocker.js:55) sets an end time, but enforcement never checks it. The probe returned `active: true` with zero seconds remaining. Session completion depends on renderer timers; a missing/throttled UI can leave blocking active. **Fix:** own expiry, completion and persistence in the main process; the UI should display backend state. Test expiration with all Productivity views closed and across sleep/resume.

14. **High — Pomodoro break state conflicts with backend focus state.** At [AppContext.tsx:593](G:/baymax/productivity/src/context/AppContext.tsx:593), entering a break stops the backend session but expects the local timer to keep running. The ensuing inactive backend event calls `handleFocusStateUpdate()` and clears that timer. An expired-but-active backend status can also recreate a full duration at lines 194–205. **Fix:** model `work`, `break`, `paused` and `ended` explicitly in the backend, with one end timestamp for each phase and one completion event.

15. **Medium — Fresh installs display an invented completed focus session.** [AppContext.tsx:276](G:/baymax/productivity/src/context/AppContext.tsx:276) inserts a 25-minute sample when real sessions are empty, even with Electron available. It affects session count and Peak Flow. **Fix:** reserve sample data for an explicit demo mode; show an empty state in the real app.

16. **High — Python and Electron independently write the same logical data, sometimes in different directories.** Electron holds `distrack-data.json` in memory and rewrites it ([store.js:12](G:/baymax/electron/productivity/store.js:12)); Python reads/modifies/replaces a file separately ([productivity_manager.py:19](G:/baymax/engine/actions/productivity_manager.py:19), line 58). An AI reclassification can be overwritten by the next tracker save. Python prefers `mochi-ultra` over `baymax`, and [schedule_manager.py:7](G:/baymax/engine/actions/schedule_manager.py:7) and [partner_chat.py:7](G:/baymax/engine/actions/partner_chat.py:7) omit the current `baymax/CoucouCreator` path altogether. **Fix:** make Electron the single persistence owner and pass validated commands/results over IPC; migrate legacy paths once. Keep a common schema for focus sessions (`date`, status, actual elapsed time), which the Python-created session currently does not follow.

17. **High — A typed Gemini request can execute twice.** [main.js:2694](G:/baymax/electron/main.js:2694) sends the same user text to an already-running Live engine and then independently calls Gemini REST. Both paths can execute actions. **Fix:** choose one executor for each request, assign a request ID, and deduplicate actions. Share the verified result with text and voice outputs. Do not have two models independently decide whether to send a message, add a task, or launch an app.

18. **High — The assistant can report success without a successful action.** [main.js:2524](G:/baymax/electron/main.js:2524) launches/closes apps without awaiting results. Several bridge fallbacks use `.catch()`, but [runMochiBridgeCmd:411](G:/baymax/electron/main.js:411) resolves failures as `{success:false}` instead of rejecting, so those fallbacks do not run. [action_loader.py:99](G:/baymax/engine/core/action_loader.py:99) converts exceptions into text, and [mochi_bridge.py:92](G:/baymax/engine/mochi_bridge.py:92) wraps that result in `success:true`. **Fix:** use typed action results (`success`, `error`, `data`, `requestId`) throughout and generate completion language only after checking the result. Add deadlines and cancellation for bridge/API calls. This is a concrete source of behavior that looks like hallucination.

19. **High — Task assignment reverses explicit roles on the partner PC.** [main.js:2485](G:/baymax/electron/main.js:2485) treats the literal role `her` as “the current user's partner.” The prompt supplies absolute `me`/`her` identifiers. In the probe, a request for `her` on a `her` PC was assigned to `me`. **Fix:** keep stable account/role IDs separate from relative words like “my partner”; validate tags against the shared schema before execution.

20. **Medium — The embedded assistant has no complete confirmation round trip.** The Live engine sends `confirm`, Electron emits `ai-confirm` ([main.js:1814](G:/baymax/electron/main.js:1814)), but the renderer has no handling UI and [mochi_runner.py:225](G:/baymax/engine/mochi_runner.py:225) has no command to resolve it. The standalone Qt UI has its own resolution path, which does not provide that path to the embedded assistant. **Fix:** connect a request-ID-based confirmation UI to the engine's existing gate, including reject/expiry handling. Do not bypass the gate to make the operation appear successful.

21. **Medium — Focus voice warnings call a nonexistent method.** [src/main.ts:191](G:/baymax/src/main.ts:191) calls `VoiceManager.speakText`, while [voice.ts:424](G:/baymax/src/core/voice.ts:424) defines `speak`. This causes the spoken distraction warning to fail. The missing `senderRole` interface field accounts for the other two TypeScript diagnostics. **Fix:** repair the bridge/types and make both frontend type checks required build steps.

**Remote access, app execution and data protection**

22. **Critical when remote sync is configured — Remote input bypasses the acceptance state.** [main.js:844](G:/baymax/electron/main.js:844) accepts `action: input` from the channel and injects it without checking an accepted session, peer identity, recipient, session ID or expiry. [remoteAccess.js:93](G:/baymax/electron/remoteAccess.js:93) automatically starts the native injector if it is stopped. A client able to publish on that channel can therefore reach the input path without the normal Accept flow; queued input after End can restart it. This is a source-level finding, not a live exploit test. **Fix first:** enforce an authenticated, accepted host session for every signal/input; bind it to the peer and a fresh nonce; reject all packets after termination; remove auto-start from untrusted input handling.

23. **High — Supabase setup grants unrestricted row access.** [supabase.js:44](G:/baymax/electron/supabase.js:44) creates `FOR ALL USING(true) WITH CHECK(true)` policies. Channel-name filters in the client are not database authorization, and the broadcast channel does not declare private authenticated membership. **Fix:** authenticated users plus pair/channel membership policies for reads/writes and private Realtime authorization. Existing deployed policy state was not inspected. See the official [RLS guide](https://supabase.com/docs/guides/database/postgres/row-level-security) and [Realtime authorization guide](https://supabase.com/docs/guides/realtime/authorization).

24. **High — Renderer security is weakened to share the Productivity bridge.** [main.js:1020](G:/baymax/electron/main.js:1020) enables Node integration in subframes and disables web security. The shared preload exposes privileged actions and settings; message handlers use `'*'` without verifying sender origin/source. **Fix:** restore web security, expose only the Productivity methods to its trusted frame/window, and validate IPC sender and arguments. Use a defined local origin and authenticated message channel. These changes follow [Electron's security guidance](https://www.electronjs.org/docs/latest/tutorial/security).

25. **High — App commands interpolate untrusted text into a shell.** [main.js:1505](G:/baymax/electron/main.js:1505) builds `start` strings from app/settings/model text; [main.js:1587](G:/baymax/electron/main.js:1587) embeds the close query in a PowerShell expression. Quoting is not a complete shell-escaping strategy. The wildcard window-title fallback can also target unrelated apps, and the Discord wrapper is treated as one executable filename rather than executable plus arguments. **Fix:** resolve a catalog app ID to a validated target, use `execFile`/`spawn` with argument arrays and `shell:false`, and close only identified app processes. Never execute a model-generated launch string as a shell command.

26. **High for private file sharing — Drive uploads change files to anyone-with-link access.** Both upload functions explicitly create `type:anyone` permissions ([gdrive.js:104](G:/baymax/electron/gdrive.js:104), line 327). **Fix:** use intended-account/folder permissions by default and make public-link sharing explicit. API keys/refresh tokens are also persisted as ordinary settings JSON ([main.js:210](G:/baymax/electron/main.js:210)); move secrets to OS-backed storage and keep them out of general renderer settings. No credential values are included in this report.

**Sync, delivery and maintenance**

27. **High for offline chat — Catch-up repeatedly reads the oldest 100 messages.** [supabase.js:569](G:/baymax/electron/supabase.js:569) orders ascending and limits to 100; [main.js:868](G:/baymax/electron/main.js:868) calls it without a since cursor. Beyond that history, newer offline messages are missed while the peer is unavailable. Catch-up emits only the final restored message to the current renderer ([main.js:895](G:/baymax/electron/main.js:895)), so the rest can remain absent until reload. **Fix:** stable pagination/cursors, idempotent merges, and a batch history-refresh event. Add an outbox with explicit pending/sent/failed states; the AI tag-send path also needs the same cloud-save logic as manual send.

28. **High for shared tasks — Reconnection can lose edits or resurrect deletions.** The peer catch-up merge at [main.js:760](G:/baymax/electron/main.js:760) only inserts unknown IDs. The cloud merge at line 919 does not represent deletions; live full-list replacement can overwrite concurrent local changes. **Fix:** version individual tasks, retain deletion tombstones, reconcile by a defined conflict rule, and apply incremental changes. Test simultaneous edits and delete-while-offline on both PCs.

29. **High — Updates can report success after a failed/partial build and overwrite local work.** [updater.js:155](G:/baymax/electron/updater.js:155) falls back from a failed Git pull to ZIP overwrite, catches copy/build failures, and still writes version metadata and restarts. It installs no changed dependencies and builds only the main frontend. **Fix:** stage a pinned revision separately, protect dirty working trees, install locked dependencies for both frontends, build/validate both and the engine requirements, then swap atomically with rollback. Abort on every failure before changing the installed version.

30. **High for reliable fixes — Build/start/setup do not validate or rebuild the full product.** [package.json:7](G:/baymax/package.json:7) builds only the main Vite app; Productivity is a separate package/build, and neither default build runs a type check. [setup.bat:55](G:/baymax/setup.bat:55) can delete the root lockfile before installing, and it does not install/build the nested frontend. A developer can edit Productivity source, run the normal build/start command, and still launch its old bundle. **Fix:** add a single verified build command covering both frontends, install both lockfiles with `npm ci`, retain reproducible dependency versions, and display the built revision in Settings. There are also two separate tracker/backend trees; document that Baymax imports `electron/productivity`, not the standalone `productivity/electron` backend.

Additional source-confirmed maintenance issues: service-account token caching is not keyed to the account ([gdrive.js:17](G:/baymax/electron/gdrive.js:17)), so replacing credentials may keep using the prior account's token until expiry; Drive uploads read and duplicate entire file buffers in the Electron main process ([gdrive.js:65](G:/baymax/electron/gdrive.js:65)), making large-video uploads a memory/UI responsiveness risk. Key the token cache to identity and use streaming/resumable transfers. These were not tested against a live Google account.

**Recommended repair order**

1. Fix remote-input authorization, channel access and shell command execution. These paths control the PC and should be corrected before further remote testing.
2. Replace the app catalog/identity layer and migrate the existing cache. Discover packaged apps and resolved shortcuts, preserve observed unknown apps, and allow utilities to be hidden without destroying usage records.
3. Repair the tracker: precise foreground intervals, buffered event decoding, idle/lock/resume handling, and a visible health status. Keep raw timing and metadata separate.
4. Route Overview, Insights, app classification and the AI through the same date-range aggregation and single data owner. Move focus expiry/Pomodoro transitions into the backend.
5. Unify AI action dispatch, typed results and confirmation handling. Remove duplicate execution and only announce verified outcomes.
6. Add the regression checks to the normal build/update pipeline, then verify behavior in an isolated application profile before changing the live user's data.

Acceptance checks should cover a Store app, a normal Win32 app, an updater-wrapped app, a portable app, Antigravity, multiple Electron apps, and a custom app. Verify one minute of foreground usage, switches, split stdout, idle/lock/resume, local midnight, empty days, weekly mode, stale-cache migration, and equal totals across all views. Verify focus expiration without an open UI, a complete Pomodoro cycle, AI failures, role assignment, two-PC offline chat pagination/deletions, and rejection of remote input before Accept and after End.

The existing probes reproduce bugs rather than prove repairs; when implementing the fixes, convert them to assertions of the correct behavior. Do not use the old rounded totals as if they were exact historical measurements—preserve them as legacy data, and begin accurate accounting from the repair date.
